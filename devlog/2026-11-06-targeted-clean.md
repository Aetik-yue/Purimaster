# 开发日志 2026-11-06（二）：定向清理功能与清理说明全面清晰化

## 今日目标

- 新增定向清理：用户指定任意目录，走与规则清理完全相同的安全管线
- 把"清理文件的说明"说得更清楚（确认时看得懂要删什么、为什么、删了会怎样）

## 设计决策

- **定向清理 = 内存中的一条临时规则**（`RuleSet::targeted` 构造器），不是新写一套删除逻辑：
  - 构造即过系统关键路径保护检查（盘符根、受保护目录当场被拒）
  - 扫描/归属/确认数字/逐文件八步校验/回收站预检全部复用，删除单点仍收敛在 platform
  - **清理时重新构造规则集**——构造即重过保护检查，不信任扫描时点（ADR-0003 延伸）
  - 风险定级 medium：确认弹窗自动带中风险徽章与警示行
- 选项：目录路径、文件类型过滤（include glob，中英文逗号分隔）、
  "跳过最近 24 小时内修改的文件"（默认勾选；定向清理是用户显式指定，可关）
- 扫描/清理命令分离（`scan_targeted`/`clean_targeted`），事件 `targeted://complete|cancelled`
  与 `clean://progress|complete`（报告弹窗复用）；清理选项打包为 `TargetedRequest`
  结构体（clippy too_many_arguments 的正路解法，顺带 API 更整洁）
- 单飞策略：定向扫描仅与自身互斥（读操作，不与规则扫描/清理互斥）；定向清理
  复用 clean_active 单飞

## 说明清晰化（第二项需求）

1. **确认弹窗逐项说明**：每个待清项目下方显示规则 description（"这是什么、为什么可清、
   有什么副作用"）——用户确认的那一刻就能读到依据，不用先回列表点详情
2. **删除方式语义说明**：确认弹窗新增一段固定说明，讲清三种方式的差别——
   回收站（可还原、空间在清空回收站后释放）/ 永久删除（绕过回收站、无法恢复）/
   预演（只列不动）；并预告"被占用文件会失败并列出，不影响其余文件"
3. **永久删除警示精确化**：从"无法从回收站恢复"改为"绕过回收站直接删除，
   事后无法通过任何方式恢复"
4. **报告措辞精确化**："试运行完成"→"预演完成（未删除任何文件）"；回收站模式
   补充"文件可在回收站中还原"（此前只说释放语义，没说怎么找回）

## 遇到的问题与解决

1. clippy too_many_arguments（clean_targeted 8/7）——选项打包 `TargetedRequest`
   （serde camelCase），前端 invoke 相应嵌套 `request: {...}`
2. `RuleSet::targeted` 需要访问私有字段——同 crate 内实现，天然合规
