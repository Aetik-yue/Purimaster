# ADR-0002: 清理规则采用"规则即数据"（TOML），与代码分离

- **状态**: 已接受
- **日期**: 2026-11-03

## 背景

垃圾清理的核心资产是"哪些路径/模式算垃圾"的规则集。浏览器缓存路径随版本变化、系统残留位置随 Windows 更新变化。若规则硬编码在 Rust 代码里，每次规则修正都要重新编译发版。

## 决策

- 清理规则全部放在 `rules/` 目录下的 **TOML 数据文件**中，由 `crates/rules` 引擎加载
- 规则条目包含：分类、目标路径（支持环境变量展开）、包含/排除 glob、风险等级
- 系统关键路径的**保护性排除**是唯一例外——硬编码在 `crates/platform`，不随数据文件变化，防止规则文件被篡改导致误删

## 备选方案

- 规则硬编码：改动成本高、无法被社区贡献规则
- JSON：注释支持差，规则文件需要大量解释性注释，TOML 更合适

## 后果

- 优点：规则修正与功能发版解耦；社区可以只提交规则 PR；规则文件本身可作为文档阅读
- 代价：需要设计规则 schema 并维护校验（加载时严格校验，非法规则拒绝启动扫描）
