# ADR-0004: 软件卸载——官方卸载器优先、注册表删除守卫、残留逐项确认

- **状态**: 已接受
- **日期**: 2026-11-06

## 背景

用户需要"删除特定软件"的能力（需求文档把"卸载器"列为后续候选）。与既有删除面（规则清理/定向清理/手动删除）不同，卸载必然触碰**注册表**——这是全新的高危面。同时必须与需求 §7 的 Non-Goal 划清界限：拒绝的是注册表"清理/优化"这类伪优化（扫描全库删"孤儿键"换性能），而卸载残留移除是功能性删除（删的是被卸载软件自己的键）。

## 决策

1. **官方卸载器优先**：只执行程序自己声明的 `UninstallString`（绝不使用 QuietUninstallString 静默卸载）。卸载器有自己的 UI/UAC，逐个串行执行并等待
2. **注册表删除守卫**（`delete_registry_tree`，硬编码拒绝清单）：
   - 只接受 `HKLM\Software\…` 与 `HKCU\Software\…` 形式的键
   - 键路径必须是 `Software\` 之下至少一级（`Software` 本身拒绝）
   - `Software\Classes\`、`Software\Microsoft\…`（除 `Software\Microsoft\Windows\CurrentVersion\Uninstall\<键>` 这一卸载键自身）一律拒绝
   - 其余任何"看起来危险"的键：不在候选列表就不该被传进来——扫描只产生名称精确匹配的候选
3. **残留逐项确认**：卸载完成后的残留（文件目录 + 注册表键）只做**候选展示**，用户逐项勾选后才删；候选由"名称精确匹配"产生（安装目录 + AppData/ProgramData 同名目录 + `Software\<名称>`），不做模糊/启发式匹配
4. **文件残留删除**走既有管线：目录删除新增 `remove_dir_tree_standalone`（canonicalize + 保护检查 + 拒绝盘符根/链接），与 `delete_file_standalone` 同层
5. **UWP/Store 应用不在本期范围**（枚举与卸载机制完全不同，且基本无注册表残留）

## 备选方案

- 静默卸载（QuietUninstallString）：用户失去对第三方卸载器的控制，否决
- 全库注册表扫描找"孤儿"：CCleaner 教训 + 误删风险，否决（这正是需求 §7 的 Non-Goal）
- 删除整个 `Microsoft` 子树下的"疑似残留"：一键伤系统，否决——只允许该程序自己的卸载键

## 后果

- 优点：卸载行为与 Windows 生态一致（官方卸载器做主删除，Purimaster 只补"最后一步"）；注册表面被守卫夹死；残留每项可见可选
- 代价：官方卸载器可能需要 UAC/弹出窗口（预期行为）；部分卸载器派生副本后立即退出，等待可能超时（标记"请稍后刷新"）；UWP 暂不支持
