# ADR-0003: 删除安全策略——回收站优先、删除时重校验、逐文件结果上报

- **状态**: 已接受
- **日期**: 2026-11-04

## 背景

Purimaster 即将提供真实的文件删除能力。清理工具一旦误删，后果不可逆，用户信任一次性归零。需求文档三原则第一条是"安全第一"，开发规范里已有删除红线（dry-run、二次确认、关键路径硬编码排除）。本 ADR 把这些约束落成实现契约。

## 决策

1. **默认删除到回收站**，永久删除是显式选项（UI 单选 + 确认弹窗中醒目标注"不可恢复"）
2. **dry-run 为一等能力**：清理接口必须支持"只执行全部安全检查、不实际删除"并返回同样的报告结构
3. **删除时重新枚举、重新校验，不信任扫描结果**：扫描与删除之间文件可能变化（被替换为链接、目录被改名、规则目标被篡改）
4. **逐文件结果上报**：单文件失败不中断整批，报告包含成功数、释放空间、失败明细（错误原因）与是否被取消
5. **删除单文件的校验顺序**（全部通过才动手）：
   - `symlink_metadata` 确认为普通文件（链接/目录/特殊文件拒绝）
   - 目标根重新过系统关键路径保护检查（`check_target`）
   - 文件 `canonicalize` 后的真实路径必须位于目标根真实路径之下（防链接/`..` 替换）
   - 文件真实路径不得命中保护路径
6. **回收站实现**使用 `trash` crate（Windows 上封装 Shell 的文件操作 API），不自行调用 Win32
7. 删除动作**只发生在 `crates/platform`**，`crates/rules` 只按规则枚举并调用该接口；两条路径都不得绕过上述校验

## 备选方案

- 自研 `IFileOperation` 封装：可控但工作量大、COM 细节多，`trash` 已满足需求
- 扫描阶段即记录文件列表、删除阶段直接照单执行：快，但违反第 3 条（TOCTOU），否决
- 批量失败即中止：对"部分文件被占用"的常见场景过于脆弱，否决

## 后果

- 优点：误删风险被多层校验夹住；dry-run 让用户可以"预览—确认—执行"；部分失败不扩大影响
- 代价：删除时重新枚举会重复扫描时间（垃圾目录规模有限，可接受）；每文件 canonicalize 有额外系统调用开销

## 2026-11-04 专项审查后的补充（已实现）

1. **回收站可行性预检**：Shell 在网络位置、回收站被禁用、文件超出回收站配额时会**静默永久删除**并返回成功。现在 Trash 模式在删除前预检（非本地固定/可移动盘、`NoRecycleFiles=1`、文件大于卷容量 5% → 拒绝并提示改用永久删除），杜绝"永久删除被报告为已回收"
2. **删除按真实路径执行**：校验后用 `canonicalize` 的真实路径删除，并在删除前最后复检原路径解析结果未变；**清理目标根本身是链接/联接点时拒绝**（防止整棵删除被重定向）
3. **个人目录保护升级**：Documents/Downloads/Desktop/Pictures/Videos/Music 改为 Known Folder API（`dirs`）解析，覆盖 OneDrive 文件夹迁移/重定向；`%LOCALAPPDATA%`、`%APPDATA%` 加入 ancestor_only；OneDrive 目录加入 sensitive
4. **清理归属与扫描一致**：clean 按与 scan 相同的规则顺序全局去重（未选中规则只参与归属），保证实际删除量不超过确认弹窗统计
5. **报告语义诚实化**：`freed_bytes` 注明回收站模式需清空回收站后才真正释放；取消后不误报"规则不存在"；读取失败条目计入 `skipped`
6. **切页不打断已确认的清理**：清理期间切换页签不再取消删除（避免部分删除无报告），报告由 `take_clean_report` 在下次进入页面时取回

## 已知限制（明确记录）

- **TOCTOU 残留**：校验与删除调用之间仍存在极小时间窗，需要同用户权限的并发进程精确抢跑（无提权边界）；句柄级删除（按句柄而非路径删除）留待后续版本
- 回收站配额按卷容量 5%（Windows 10/11 默认）估算；用户自定义的更小卷级配额无法预检
- 无法可靠检测"文件被占用"——以删除时的错误上报为准；被占用文件（共享冲突）会计入失败明细
- 部分网络盘无回收站支持被预检拒绝；未来可提供"该卷显式回退永久删除"的策略调研
