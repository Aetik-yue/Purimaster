# 文档编写规范

- **版本**: v0.1 ｜ **日期**: 2026-11-03 ｜ 适用范围：Purimaster 全部仓库文档

---

## 1. 目录与命名

| 位置 | 放什么 |
|------|--------|
| `README.md`（根） | 项目门面：是什么、状态、文档导航 |
| `docs/requirements.md` | 需求文档（唯一，持续演进） |
| `docs/architecture.md` | 技术栈与架构（唯一，持续演进） |
| `docs/standards/` | 各类规范（documentation.md、process.md） |
| `docs/decisions/NNNN-slug.md` | 架构决策记录 ADR，四位编号 + kebab-case |
| `devlog/YYYY-MM-DD-slug.md` | 开发日志，一天可多篇，slug 用英文 kebab-case |

- 文件名一律英文 kebab-case（ADR 编号前缀除外）；**内容用中文**。
- 代码、命令、标识符、专有名词保持英文原文。

## 2. 文档头

每篇文档首部必须有一个元信息块（ADR 和 devlog 用轻量版）：

```markdown
# 标题

- **版本**: v0.1
- **日期**: 2026-11-03
- **状态**: 草稿 | 已评审 | 已废弃
```

## 3. 中文文案风格

遵循《中文文案排版指北》的核心规则：

1. 中英文之间加空格：`使用 Rust 编写`，不是 `使用Rust编写`
2. 中文与数字之间加空格：`耗时 30 秒`
3. 全角标点（，。：；！？），英文/代码语境用半角
4. 不滥用感叹号；技术文档不用"您"，统一用"你"
5. 专有名词保持官方大小写：Windows、GitHub、Tauri，不写"微软 windows"

## 4. Markdown 风格

- 标题从 `#` 开始且每篇只有一个 `#`，层级不跳级（`#` → `##` → `###`）
- 列表缩进用 2 空格；表格用于结构化对比，不用表格堆砌长段落
- 代码块必须标注语言（```rust / ```bash / ```text），目录树用 `text`
- 链接用相对路径：`[需求文档](../requirements.md)`
- 图片存 `docs/assets/`，引用相对路径

## 5. 文档类型模板

### ADR（`docs/decisions/NNNN-slug.md`）

```markdown
# ADR-NNNN: 标题

- **状态**: 提议 | 已接受 | 已废弃（被 ADR-MMMM 取代）
- **日期**: YYYY-MM-DD

## 背景（为什么需要做这个决策）
## 决策（决定了什么）
## 备选方案（考虑过什么，为什么没选）
## 后果（带来什么好处和代价）
```

ADR 编号只增不减、已接受的 ADR 不修改正文，推翻时写新 ADR 并标注取代关系。

### 开发日志（`devlog/YYYY-MM-DD-slug.md`）

```markdown
# 开发日志 YYYY-MM-DD：一句话主题

## 今日目标
## 完成情况
## 遇到的问题与解决
## 决策记录（如有，链接到 ADR）
## 明日计划
```

### 需求/架构文档

见 `docs/requirements.md`、`docs/architecture.md` 的现有结构，演进时递增版本号并在文末"变更记录"追加一行。

## 6. 变更管理

- 需求、架构文档的正向演进：直接修改 + 版本号 +1 + 变更记录
- 推翻既有决策：必须走新 ADR，不得静默改旧文档
- 文档与代码同 PR 提交：改了行为不改文档，视为未完成
